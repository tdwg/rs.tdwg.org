# BDQ release inputs

Inputs for processing the Biodiversity Data Quality (BDQ) standard for the public review at `bdq-public-review.rs.tdwg.org` ([tdwg/bdq#340](https://github.com/tdwg/bdq/issues/340); plan: [`tg2/_make_review/deployment_rs_tdwg_org.md`](https://github.com/tdwg/bdq/blob/master/tg2/_make_review/deployment_rs_tdwg_org.md), Section 8).

`bdq-revisions-2026-11-09/` holds the inputs for the five simple vocabularies (`bdqdim`, `bdqenh`, `bdqcrit`, `bdquc`, `bdqval`):

- `config.yaml`: the release declaration (standard, vocabularies, namespaces, List of Terms documents);
- `<prefix>.csv`: one release-input CSV per namespace;
- `mappings/<dataset>/`: the BDQ column mapping files and `namespace.csv` for each dataset. They follow BDQ's own RDF (plan Section 8.3).

These files were generated from `tg2/_review/vocabulary/*_term_versions.csv` and the List of Terms `document_configuration.yaml` files in [tdwg/bdq](https://github.com/tdwg/bdq).

They were generated by `bdq_to_rs.py` (from tdwg/bdq master `10a5d682`):

```bash
python -I bdq-revisions/bdq_to_rs.py <path to tdwg/bdq> <path to rs.tdwg.org> 2026-11-09
```

`bdq_to_rs.py` is for the public review only. It bootstraps these inputs from the files in tdwg/bdq, and is intended to be replaced by authoritative information kept in this repository: from now on, the files in the release directory are the source and are edited directly. Rerunning the script overwrites them.

## Processing

From the `process` directory:

```bash
python process.py --dry-run --config bdq-revisions/bdq-revisions-2026-11-09/config.yaml
python process.py --config bdq-revisions/bdq-revisions-2026-11-09/config.yaml
```

`process.py` creates each new term list's mapping files from the templates. After processing, copy the BDQ mapping files into the dataset directories:

```bash
cd bdq-revisions/bdq-revisions-2026-11-09/mappings
for d in */; do cp "$d"* "../../../../$d"; done
```

After the first run, set `new_term_list: false` in `config.yaml` before any rerun of the same release. The templates are then not copied again, so the BDQ mapping files are kept.
